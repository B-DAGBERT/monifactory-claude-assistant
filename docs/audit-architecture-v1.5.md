# Audit d’architecture V1.5

Base d’audit `b8e1b92`, vérifiée sur `origin/main`. Ce commit publie le code d’isolation
des mondes du lot 5. Les commits `a7d78e9`, `062469c` et `19068d1` couvrent respectivement
la provenance, le routage et la migration explicite. Les preuves Windows et réseau du
[lot 5](isolation-mondes.md) restent à obtenir. Le script serveur est identique à celui
de `d943bad`. La branche du lot 2, dont le dernier commit est `6c4f101`, n’est pas dans
`main`. Les skills sont publiés sur une branche indépendante.

L’audit a été effectué en lecture seule. Compilation, mesures et reproductions utilisent
des copies Git ou des fixtures. Le répertoire de développement d’origine contient
`.serena/`, hors du périmètre. Les historiques des utilisateurs et le serveur n’ont pas
été utilisés pour les essais.

## Architecture

| Couche                       | Responsabilité et couplages                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Entrée et supervision Python | Les lanceurs historiques appellent `startup` puis la vérification de mise à jour sous verrou. `app.py` compose quatre contrôleurs autour d’une boucle Tk. Les workers publient leurs résultats dans la file d’événements. Les exceptions de lancement et la réinscription des callbacks demandent un traitement spécifique.                                                                          |
| Contrôleurs Python           | `application/game.py` tient le contexte de jeu. `projects.py` orchestre pause et progression, `conversation.py` les tours et fiches, `interface.py` les commandes et vues. Des invariants concernent plusieurs contrôleurs, dont l’époque de l’objectif et la portée du monde. Les tests vérifient déjà l’absence de collision de méthodes.                                                          |
| Données Python               | `game/` sépare état, inventaire, filons, recettes, stocks, recherches, objectifs et file durable. `persistence.py` fournit le remplacement atomique avec copie précédente. `paths.py` sépare code et données, `world_scope.py` protège les chemins et la portée du lot 5.                                                                                                                            |
| IA et plateforme             | `providers/` garde deux adaptateurs CLI et sessions indépendants. Le transport Codex vérifie le mode lecture seule. Claude reçoit une liste d’arguments et des outils de lecture/recherche. Le panneau local de Discussion vérifie jeton, origine et hôte. `audio.py` charge les dépendances de reconnaissance et voix dans ses workers. `platform/` isole capture, focus et raccourcis Mac/Windows. |
| Java Forge                   | `AssistantIA` et `Client` raccordent les événements et les écrans. `EcranAssistant` délègue aux onglets. `Pont` assure les échanges. Le rendu des repères utilise des buffers dédiés et la luminosité restaure la texture. La taille de ces classes ne démontre pas un défaut.                                                                                                                       |
| EMI et GregTech              | `InventaireJoueur` consolide les sources natives. `CycleArbreEmi`, `MachinesEmi`, `PlanMachines` et `SuiviLotsEmi` distinguent stocks, réservations et réceptions. `RetraitCoffre` et `EnvoiMachine` valident les cases réelles et attendent les confirmations natives. Les mixins optionnels et les handlers conservent les intégrations du pack.                                                   |
| Filons et KubeJS             | `Filons` orchestre scan, mémoire et vue. `FilonMemoire`, les classes de style et les écrans isolent une partie de la logique. KubeJS client observe le monde et gère les exports. `IdentiteMonde`, `SessionMonde` et les mixins d’origine séparent connexions et dimensions. Le serveur facultatif fournit les observations accessibles, avec les permissions FTB.                                   |

Le relevé statique des 58 modules Python trouve 140 dépendances directes au niveau module et
149 en incluant les imports locaux. Aucun cycle entre modules distincts n’a été trouvé par ce
relevé. Les parcours des contrôleurs ne justifient pas de remplacer leur composition.
Les modules de jeu s’importent sans les bibliothèques d’interface et de voix dans le test dédié.
Le double parcours des recettes et la publication concurrente des index ont été examinés
séparément. Les communications natives des machines et les règles de stock restent des
contrats à caractériser avant toute modification.

La revue de persistance a ensuite reproduit un défaut P1 supplémentaire, **R4**. L’effacement
du plan écrivait deux fois et remplaçait la copie `.bak` complète par un état intermédiaire
déjà vidé de son objectif. Sur une copie contenant un objectif en pause, les octets de
l’ancienne version n’étaient plus dans la sauvegarde immédiate. Le changement minimal est
d’écrire l’état final une fois et de le publier en mémoire après succès. Les tests vérifient
la copie complète, le cas objectif seul et le refus d’écriture. Coût et risque faibles,
réversion du commit possible.

**R5, P1**. L’origine d’une proposition d’action destructive repose sur le prompt. Un texte
simulé contenant `effacer_plan` appelle le gestionnaire même quand le texte visible ne parle
que d’une recette. Le test a utilisé un gestionnaire fictif, sans suppression. La correction
R4 conserve le dernier projet complet, tandis qu’une règle de consentement côté jeu demande
de définir comment préserver les commandes vocales existantes. Cette décision et la validation
de bout en bout restent ouvertes.

**B6, P2.** Après 46 secondes, le fichier historique restant pouvait remplacer son
propre reçu « acceptée » ou « refusée » par « expirée ». La comparaison stricte garde
le reçu du même numéro, avec reproduction des deux états sur redémarrage.

Le contrôle par nom et motifs sur les fichiers suivis n’a pas détecté de configuration
privée attendue, jeton ou clé privée correspondant aux motifs recherchés. Les dépendances
Python installées passent `pip check`. Ruff, Prettier, le contrôle de formatage Java et
la compilation Forge JDK 17 passent sur la copie de référence. L’exécution initiale de
la suite dans un environnement sans socket local a isolé dix erreurs de droits dans les
tests HTTP du panneau. Les résultats en environnement adapté figurent dans le
[rapport de qualification](qualification-v1.5.md).
